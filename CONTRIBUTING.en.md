# Contributing to wayvpet Wayland Overlay

Thank you for your interest in contributing to the current Rust implementation
of wayvpet.

## Getting Started

### Prerequisites

- Wayland compositor with layer shell support
- Stable Rust (edition 2021)
- Wayland development headers (`libwayland-dev` or `wayland-devel`)
- `pkg-config` and `make`

`wayland-scanner` and `wayland-protocols` are not required for normal builds;
the bindings are generated by the Rust crates.

### Building

```bash
git clone https://github.com/athomo001/wayvpet.git
cd wayvpet
cargo build             # Development build
cargo build --release   # Release build
```

### Running

```bash
./target/release/wayvpet -c wayvpet.conf -w
```

## Development Workflow

### Code Style

- Run `cargo fmt --all` before committing
- Follow the existing code patterns
- Use meaningful variable names

### Making Changes

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/my-feature`
3. Make your changes
4. Test thoroughly
5. Submit a pull request

### Commit Messages

Use conventional commits:

```
feat: add new feature
fix: resolve bug
docs: update documentation
refactor: improve code structure
```

## Code Structure

```
crates/
├── wayvpet/         # Wayland overlay and main CLI
├── wayvpet-common/  # Configuration and pure logic
├── wayvpet-config/  # Configuration window
└── wayvpetctl/      # IPC client
```

## Testing

```bash
# Run unit tests
make test

# Run with debug logging
./build/wayvpet -c wayvpet.conf -w

# Run the focused checks used by CI
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
```

## Reporting Issues

When reporting bugs, please include:

- Your compositor (Sway, Hyprland, etc.)
- Config file contents
- Debug output (`enable_debug=1`)

## Questions?

Open an issue or reach out to the maintainer.

Thanks for helping make wayvpet better! 🎉
